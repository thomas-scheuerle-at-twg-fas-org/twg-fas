# Contributing to TWG·FAS

Thank you for your interest in contributing to the **Technical Working Group for Formal Automotive Systems (TWG·FAS)**.

TWG·FAS is an independent, vendor-neutral initiative dedicated to developing open standards for formal behavioral representation in AI-driven automotive systems.

We welcome contributions from individuals, academia, industry, public institutions, and open-source communities.

---

# Principles

All contributions should align with the core principles of TWG·FAS:

* Technical excellence
* Evidence-based engineering
* Openness and transparency
* Vendor neutrality
* Respectful collaboration
* Long-term interoperability

Technical discussions should focus on engineering arguments, supporting evidence, and practical experience rather than organizational interests.

---

# Ways to Contribute

You do **not** need write access to contribute.

We encourage community participation through:

* Reporting issues
* Suggesting improvements
* Opening feature requests
* Reviewing draft specifications
* Participating in technical discussions
* Proposing new ideas
* Providing reference implementations
* Contributing test cases and examples

Every constructive contribution helps improve the standard.

---

# Repository Access

Direct write access to this repository is **not granted automatically**.

During the founding phase, write access is provided only after personal contact with the project founder or the TWG·FAS editors.

This approach helps establish a trusted and collaborative working environment while the governance structure of the working group is being formed.

If you would like to become an active contributor, please contact us through:

* the contact form on the TWG·FAS website, or
* the published project email address.

After an introductory discussion, contributors may be invited to join the repository with write access.

---

# Contribution Workflow

The preferred workflow is:

1. Discuss the idea before starting significant work.
2. Open an Issue describing the proposal.
3. Collect technical feedback.
4. Prepare the proposed changes.
5. Submit a Pull Request (for repository members) or share the proposed changes for review.
6. Address review comments.
7. Merge after technical consensus has been reached.

Large changes should always be discussed before implementation.

---

# Specifications

Specification documents are developed as working drafts.

When proposing changes:

* explain the motivation;
* describe the technical rationale;
* consider compatibility with existing drafts;
* discuss potential implementation impacts; and
* reference related proposals whenever possible.

Normative changes should include sufficient explanation for reviewers to evaluate the proposal.

---

# Document Style

Specification documents should strive for:

* precise language;
* unambiguous terminology;
* consistent definitions;
* clear separation between normative and informative text; and
* reusable examples where appropriate.

Where possible, use RFC 2119 / RFC 8174 terminology ("MUST", "SHOULD", "MAY", etc.) for normative requirements.

---

# LaTeX Documents

Most specifications are maintained in LaTeX.

Please:

* keep formatting changes separate from technical changes;
* avoid unnecessary whitespace-only modifications;
* place figures in the appropriate document directory;
* keep bibliographic references consistent; and
* ensure documents compile successfully before submission.

---

# Code Contributions

Reference implementations, tools, examples, and test suites should:

* be well documented;
* include appropriate licensing information;
* follow the project's coding conventions;
* include tests whenever practical; and
* remain independent of proprietary technologies whenever possible.

---

# Decision Making

TWG·FAS seeks technical consensus.

When consensus cannot be reached, decisions will follow the governance process defined by the working group.

Constructive disagreement is encouraged when supported by technical reasoning.

---

# Code of Conduct

All participants are expected to follow the project's Code of Conduct.

Professional, respectful, and inclusive collaboration is essential to the success of an open standards initiative.

---

# Questions

If you are unsure where to begin, or would like to become an active contributor, please contact the project through the TWG·FAS website or by email.

We look forward to building the future of formal automotive standards together.
