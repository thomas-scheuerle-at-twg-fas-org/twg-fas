# TWG-FAS Governance

This document defines how the Technical Working Group for Formal Automotive Systems (TWG-FAS) organizes decision-making, roles, accountability, and standards development.

Status: Living document (founding phase, draft governance)

## 1. Purpose

TWG-FAS is an open, vendor-neutral, non-profit standards initiative.

The governance model exists to:

- keep technical work open and transparent
- protect vendor neutrality
- make decisions predictable and auditable
- ensure that technical merit drives outcomes
- support long-term interoperability and public trust

## 2. Scope

This governance applies to:

- specification development in this repository
- official TWG-FAS working drafts and publications
- decisions on process, roles, and publication status
- behavior in official TWG-FAS collaboration channels

It complements, and does not replace:

- [CHARTER.md](CHARTER.md)
- [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md)
- [CONTRIBUTING.md](CONTRIBUTING.md)

## 3. Governance Principles

All governance decisions should follow these principles:

- Openness: process and rationale are documented whenever legally possible.
- Vendor neutrality: no single company or actor controls outcomes.
- Consensus-first: decisions should seek broad technical alignment before voting.
- Technical merit: arguments are evaluated by evidence and engineering quality.
- Traceability: decisions and changes are recorded in repository artifacts.
- Inclusiveness: participation is open to individuals and organizations.

## 4. Governance Structure

The working structure in the founding phase is:

- Contributors: anyone who submits proposals, reviews, issues, comments, tests, or implementations.
- Editors: maintain draft quality, terminology consistency, and document coherence.
- Maintainers: manage repository operations, release mechanics, and publication state.
- Working Groups: topic-focused teams (for example language design, semantics, verification, conformance).
- Founding Coordination Team: bootstrap function for early-stage continuity until elected governance is activated.

Detailed responsibilities are defined in:

- [governance/roles-and-responsibilities.md](governance/roles-and-responsibilities.md)

## 5. Decision Model

TWG-FAS follows a consensus-first model:

1. discuss the issue and alternatives openly
2. capture objections and proposed resolutions
3. call for consensus with clear decision text
4. if needed, escalate to a time-boxed vote

Consensus is preferred over simple majority.

When consensus cannot be demonstrated in reasonable time, a documented vote process is used.

Decision rules, vote thresholds, conflict-of-interest handling, and appeals are defined in:

- [governance/decision-making.md](governance/decision-making.md)

## 6. Standards Development Process

TWG-FAS standards progress through transparent lifecycle states from proposal to publication, including review, change requests, implementation evidence, and conformance expectations.

The full lifecycle and entry/exit criteria are defined in:

- [governance/standards-development-process.md](governance/standards-development-process.md)

## 7. Transparency, Meetings, and Records

To maintain public trust and technical traceability, governance artifacts should be documented in the repository.

This includes:

- agendas
- meeting notes
- decisions and rationale
- vote records
- status changes of draft specifications

Recordkeeping conventions are defined in:

- [governance/meetings-and-records.md](governance/meetings-and-records.md)

## 8. Code of Conduct and Enforcement

All participants must follow the project Code of Conduct.

Behavioral or process violations may result in moderation actions, temporary restrictions, or suspension from TWG-FAS channels and decision activities.

Enforcement actions should be proportionate, documented, and aligned with impartial process.

## 9. Intellectual Property and Licensing Alignment

Governance decisions should stay aligned with TWG-FAS open-standard goals:

- specification text intended for open publication
- reference implementations intended for permissive licensing
- disclosure of known essential patent claims encouraged

Licensing details remain governed by project licensing documents and publication policy.

## 10. Governance Changes

This file is intentionally live and may evolve.

Changes to governance should:

1. be proposed through an issue or pull request
2. include motivation and expected impact
3. be reviewed publicly
4. be accepted through the governance decision process

For significant governance changes, maintainers should provide a transition note explaining what changed and why.

## 11. Transition to Elected Governance

During the founding phase, some responsibilities are performed by the Founding Coordination Team.

TWG-FAS intends to transition to elected officers once participation is broad enough to support stable representation.

The transition plan should define:

- eligibility to vote and stand for roles
- election cadence
- term limits
- handover process
